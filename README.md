# Duty-shift-swap


## Назначение

Обмен сменами дежурств: график, запросы обмена, подтверждение старшими, история замен.

## Роли и сценарии

Сотрудник (EMPLOYEE):
- просматривает свои смены и детали смены;
- выбирает свою свободную смену и смену коллеги, смотрит сравнение «Сейчас» и «После обмена», отправляет запрос;
- следит за исходящими запросами;
- принимает или отклоняет входящие запросы.

Старший (SENIOR):
- пользуется всеми экранами сотрудника;
- одобряет или отклоняет запросы, которые принял сотрудник;
- смотрит историю завершённых запросов;
- просматривает график всех смен (добавление, редактирование и удаление в ЛР1 только показаны в диалогах и не выполняются).

## Экраны

| Адрес | Экран | Кто видит |
|---|---|---|
| /login | Вход | не вошедшие |
| /register | Регистрация | не вошедшие |
| / | Мои смены | вошедшие |
| /shift/:id | Детали смены | вошедшие |
| /select-shift?shiftId=... | Выбор смены для обмена | вошедшие |
| /swap-requests | Запросы обмена (исходящие и входящие) | вошедшие |
| /senior-queue | Очередь старшего: ждут решения, история, управление графиком | только SENIOR |

## Стек

React, TypeScript, Vite, MUI, React Router, npm.

## Запуск frontend

```
cd frontend
npm install
npm run dev
```

После запуска приложение доступно по адресу, который покажет Vite (обычно http://localhost:5173/). 

## Запуск Backend (FastAPI)
1. Перейдите в папку `backend`.
2. Создайте виртуальное окружение: `python -m venv venv`
3. Активируйте его: `source venv/bin/activate`
4. Установите зависимости: `pip install -r requirements.txt`
5. Убедитесь, что PostgreSQL запущен, и создана база `duty_shift_swap`.
6. Создайте `backend/.env` и укажите `DATABASE_URL` (например, `postgresql+psycopg://пользователь:пароль@localhost:5432/duty_shift_swap`) и `JWT_SECRET`. Секрет должен быть случайным и не короче 32 символов; создать его можно командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Не публикуйте `.env`. При необходимости задайте `ACCESS_TOKEN_MINUTES` и `REFRESH_TOKEN_DAYS` (по умолчанию 15 минут и 7 дней).
7. При необходимости заполните тестовую БД данными: `python seed.py`. Внимание: скрипт удаляет существующие таблицы и данные!
8. Запустите сервер: `uvicorn app.main:app --reload`
9. Документация API доступна по адресу: `http://127.0.0.1:8000/docs`

## Аутентификация API

- `POST /auth/register` создаёт сотрудника; `POST /auth/login` возвращает access и refresh токены.
- Приватные маршруты требуют заголовок `Authorization: Bearer <access token>`. В Swagger токен можно указать через кнопку **Authorize**.
- `POST /auth/refresh` принимает JSON с полем `refresh_token` и возвращает access token. `POST /auth/logout` принимает тот же JSON и отзывает текущую refresh-сессию.
- После выхода ранее выданный access token действует до окончания срока. Список пользователей и управление данными пользователей доступны старшему; сотрудник может просматривать свой профиль и смены, а также кандидатов для обмена.

В режиме разработки Vite перенаправляет запросы `/api` на FastAPI по адресу `http://127.0.0.1:8000`. Если backend запущен на другом адресе, задайте `API_PROXY_TARGET` при запуске Vite.

Frontend хранит access и refresh токены в `localStorage`; скрипты страницы могут их прочитать, поэтому защита от XSS особенно важна. При восстановлении сессии после перезагрузки, если access недействителен, приложение пробует обновить его через refresh.
